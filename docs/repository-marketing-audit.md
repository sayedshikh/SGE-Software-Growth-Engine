# Repository Marketing Audit Checklist

- [ ] Product/problem headline is clear in the first screen
- [ ] Audience and use cases are specific
- [ ] Claims are supported and caveated
- [ ] Real screenshots/demo are present (no fabricated UI)
- [ ] Installation/demo instructions are clear
- [ ] Feature documentation and FAQ are available
- [ ] Support/contact path is visible
- [ ] Pricing and licensing link are accurate
- [ ] Changelog and release status are maintained
- [ ] Topics are relevant and not keyword-stuffed
- [ ] Security/privacy boundaries are documented
- [ ] Checks/build status badge refers to an actual workflow
- [ ] Download integrity checks are documented if binaries are provided
- [ ] No secrets or customer data in history/files
- [ ] README links are checked
- [ ] Public issues discourage sensitive disclosures

Score only verified checklist items; do not treat the checklist as a security certification or SEO ranking predictor.
