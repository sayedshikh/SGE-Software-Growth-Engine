# SC130 — Public Website Architecture & Positioning

## Mission
The public website is a portfolio and marketing hub for all software products, commercial listings, and projects in development. It is not an SGE-only marketing site.

## Primary visitor paths
1. Discover portfolio/project → product/project profile → relevant use case, evidence/story, resource → demo/trial or marketplace when a verified purchase path exists.
2. Discover a problem via search → problem-solving page/guide/comparison → free utility or relevant product → optional marketplace listing.
3. Discover engineering story → inspect problem, constraints, recorded verification and limitations → relevant project profile → follow updates/contact.
4. Discover free tools → use browser-based utility where supported → review assumptions/privacy scope → optional relevant product.

## Site sections
- Homepage: portfolio overview, categories, links to portfolio, free tools, engineering stories, development updates and search.
- Portfolio: commercial listings and separate in-development projects; careful status language and marketplace links only where available.
- Product/project profiles: problem, audience, verified scope, status, evidence, limitations, relevant resources and next step.
- Engineering Stories: investigations, implementation/verification records, limitations and project links.
- Development Updates: milestone/change records; do not imply new testing without evidence.
- Free Tools & Resources: standalone utilities, guides, comparisons and clear scope/privacy notes.
- Research workspaces: site search, SEO/content/distribution/site-intelligence tools; each should describe data provenance and whether data is live, imported, manually supplied or heuristic.
- Distribution & growth resources: research and planning tools with human approval for externally consequential actions.

## Product status categories (suggested)
- Commercial listing: seller link exists; listing/package/checkout availability should be checked on seller site.
- Free trial / early access: explicit trial link and limitations.
- Active development: not presented as finished or fully validated.
- Research tool/workspace: distinguish operational functionality from data sources and validation.
- Archived/deferred: clearly mark or omit from current portfolio navigation.

## Purchase pathway
Site profile → evidence and scope → demo/free trial (if available) → purchase/download on Payhip, Gumroad or another verified platform. No invented checkout links, guarantees or testimonials.

## Content and SEO principles
- One page per distinct user intent; avoid overlapping pages competing for the same query.
- Problem-solving pages connect to useful guides, free tools and product pages naturally.
- Comparisons disclose criteria, assumptions and date of review.
- Product pages link to relevant stories, updates, FAQ, guides and support/contact.
- Stories link back to the relevant product/project profile and related content.
- Internal links should be useful and not manufactured sitewide.
- Structured metadata and sitemap should be audited against the actual files.
